# 2026-09-08 — Old-Map-First V2 weighted local scan matching

- What changed:
  - Added `slam_toolbox/include/slam_toolbox/oldmap_mapper.hpp` with `OldMapMapper`, a subclass that defaults to upstream behavior unless `oldmap_scan_weighting_enabled=true`.
  - `slam_toolbox/src/slam_mapper.cpp` constructs `OldMapMapper` and exposes Old-Map V2 parameters. Other profiles keep the custom matcher disabled.
  - V2 initial local matching always retains the ordinary recent running buffer and additionally selects sparse historical keyframes near the predicted pose. Scan 1 is retained as trusted history, keyframe spacing is `0.5 m`, search radius `3.0 m`, and at most `40` historical keyframes are added per local match.
  - Raw temporal confidence is `c_raw(i)=0.25+0.75*exp(-i/70)`. Active weights are normalized by the strongest active reference to preserve old>new ordering without suppressing the absolute matcher response in new regions.
  - Karto's Gaussian correlation-grid smear shape is retained but each reference scan's kernel amplitude is scaled by its active temporal confidence; cell fusion remains max-based.
  - Follow-up implementation change: `OldMapMapper` now mirrors Karto `AddEdges()` when enabled so the local `LinkNearChains()` stage can use the same temporal weighted matcher. Previous-scan linking, running-chain linking, near-chain discovery, response threshold, closest-scan link and covariance-weighted mean fusion follow upstream logic; only the near-chain `MatchScan(..., doPenalize=false)` is replaced by `WeightedMatchScan(..., do_penalize=false)` with old>new weights inside that chain.
  - As a result, both local frontend stages that can alter the new scan pose are now temporal-weighted: the initial sequential/local correction and the near-chain local correction.
  - `oldmap_toolbox.launch.py` retains the Ceres policy: first pose fixed, `node_gap<=5`, `5x->1x`, decay `70`, long-gap/loop edges `1x`, release disabled (`1.0->1.0`).
  - Loop-closure coarse/fine matching itself remains unweighted/upstream so loop closure stays an independent evidence source.
  - Recorder provenance remains `new_room_oldmap_toolbox_v2`; `oldmap_mapper.hpp` is already included in provenance hashes, so the pre-near-chain and current implementations have different exact source hashes and must not be mixed in one formal batch.
- Why:
  - The first V2 implementation weighted the initial sequential/local match but Karto `LinkNearChains()` still performed an equal-confidence local match afterward and could change the scan pose. This left one local frontend path inconsistent with the intended `S1>S2>S3...` hierarchy. The follow-up change closes that gap without biasing the loop-closure detector.
- Affected runs:
  - Old-Map V2 diagnostic runs only. Any V2 run recorded before the weighted-near-chain commit must be treated as a different implementation hash and not mixed with the current batch.
- Does baseline need rerun?:
  - No official `hospital_v2` protocol change. Non-oldmap profiles have `oldmap_scan_weighting_enabled=false` and still call upstream `karto::Mapper::Process()`.
