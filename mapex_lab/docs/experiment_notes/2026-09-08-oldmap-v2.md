# 2026-09-08 — Old-Map-First V2 weighted sequential scan matching

- What changed:
  - Added `slam_toolbox/include/slam_toolbox/oldmap_mapper.hpp` with `OldMapMapper`, a subclass that defaults to upstream behavior unless `oldmap_scan_weighting_enabled=true`.
  - `slam_toolbox/src/slam_mapper.cpp` now constructs `OldMapMapper` and exposes Old-Map V2 parameters. Other profiles keep the custom matcher disabled.
  - V2 sequential matching always retains the ordinary recent running buffer and additionally selects sparse historical keyframes near the predicted pose. Scan 1 is retained as trusted history, keyframe spacing is `0.5 m`, search radius `3.0 m`, and at most `40` historical keyframes are added per local match.
  - Raw temporal confidence is `c_raw(i)=0.25+0.75*exp(-i/70)`. Active weights are normalized by the strongest active reference to preserve old>new ordering without suppressing the absolute matcher response in new regions.
  - Karto's Gaussian correlation-grid smear shape is retained but each reference scan's kernel amplitude is scaled by its active temporal confidence; cell fusion remains max-based.
  - `oldmap_toolbox.launch.py` now enables this scan matcher while retaining V1 Ceres policy: first pose fixed, `node_gap<=5`, `5x->1x`, decay `70`, long-gap/loop edges `1x`, release disabled (`1.0->1.0`).
  - Loop-closure matching itself remains unweighted/upstream so loop closure stays an independent evidence source.
  - Recorder provenance changed from `new_room_oldmap_toolbox_v1` to `new_room_oldmap_toolbox_v2` and now hashes the matcher, SMapper glue, and Ceres solver.
- Why:
  - Old-Map V1 implemented `S1>S2>S3...` only at the Ceres pose-graph layer. The ordinary Karto sequential matcher still treated all active reference scans equally. V2 applies the same temporal confidence idea before pose-graph optimization while avoiding the unsafe interpretation that every scan must directly match scan 1.
- Affected runs:
  - Old-Map V2 diagnostic runs only. Do not mix Old-Map V1 results with V2.
