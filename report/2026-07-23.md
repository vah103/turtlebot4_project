## 1. Đã thực hiện

- Kết nối SSH vào Raspberry Pi của TurtleBot4 và xác nhận ROS 2 Jazzy đang hoạt động.
- Kiểm tra các topic chính trong namespace `/bot1`: pin, LiDAR, odometry, TF, trạng thái dock và topic điều khiển.
- Phát hiện LiDAR được hệ thống nhận nhưng motor không quay và `/bot1/scan` chưa phát dữ liệu.
- Bật lại motor LiDAR bằng service `/bot1/start_motor`.
- Xác nhận LiDAR phát `LaserScan` ổn định khoảng `7.58 Hz` và có dữ liệu khoảng cách thực.
- Kiểm tra diagnostics, odometry và chuỗi TF `odom -> base_link -> rplidar_link`.
- Cho robot rời dock thành công bằng action `/bot1/undock`.
- Chạy SLAM trên laptop Dell, điều khiển robot đi quét lại phòng lab và lưu map mới.
- Chạy Localization bằng AMCL với map đã lưu và đặt initial pose bằng công cụ **2D Pose Estimate** trong RViz.
- Chạy Nav2, xử lý lỗi lifecycle của `planner_server` và `bt_navigator`, sau đó điều hướng robot tới nhiều goal thành công.
- Đưa map mới và ảnh RViz lên GitHub sau phiên lab.

## 2. Lệnh và kết quả đáng chú ý

### Kết nối và kiểm tra ROS 2

```bash
ssh ubuntu@<ROBOT_IP>
ros2 topic list
```

Các topic quan trọng đã xuất hiện:

```text
/bot1/battery_state
/bot1/odom
/bot1/scan
/bot1/tf
/bot1/tf_static
/bot1/cmd_vel
/bot1/dock_status
```

Kiểm tra pin:

```bash
ros2 topic echo --once /bot1/battery_state
```

Kết quả xác nhận:

```text
percentage: khoảng 0.71
voltage: khoảng 15.53 V
temperature: khoảng 35.05 °C
present: true
```

### Khắc phục LiDAR không quay

Kiểm tra thiết bị và service:

```bash
ls -l /dev/RPLIDAR /dev/ttyUSB0 2>&1
ros2 service list | grep -E 'start_motor|stop_motor|rplidar'
```

Kết quả:

```text
/dev/RPLIDAR -> ttyUSB0
/dev/ttyUSB0 tồn tại
/bot1/start_motor
/bot1/stop_motor
```

Bật motor LiDAR:

```bash
ros2 service call /bot1/start_motor std_srvs/srv/Empty "{}"
```

Kết quả:

```text
response:
std_srvs.srv.Empty_Response()
```

Đo tần số quét:

```bash
ros2 topic hz /bot1/scan
```

Kết quả:

```text
average rate: khoảng 7.58 Hz
```

Kiểm tra một bản tin quét:

```bash
ros2 topic echo --once /bot1/scan | sed -n '1,35p'
```

Kết quả xác nhận:

```text
frame_id: rplidar_link
range_min: 0.15 m
range_max: 12.0 m
có các giá trị khoảng cách thực khoảng 3.17 m và 4.41 m
```

### Diagnostics và TF

```bash
ros2 topic echo --once /bot1/diagnostics_agg | grep -E 'level:|name:|message:'
```

Các thành phần đã báo `OK`:

- Battery
- Dock
- Hazards
- IMU
- Wheels
- Lidar

Camera, Mouse và Joystick từng báo không có dữ liệu. Các lỗi này không ngăn bài thử SLAM bằng LiDAR và Nav2 trong phiên làm việc này, nhưng chưa được xử lý triệt để.

Kiểm tra TF:

```bash
timeout 8 ros2 run tf2_ros tf2_echo odom base_link \
  --ros-args \
  -r /tf:=/bot1/tf \
  -r /tf_static:=/bot1/tf_static

timeout 8 ros2 run tf2_ros tf2_echo base_link rplidar_link \
  --ros-args \
  -r /tf:=/bot1/tf \
  -r /tf_static:=/bot1/tf_static
```

Kết quả xác nhận:

```text
odom -> base_link: có transform động
base_link -> rplidar_link:
  Translation: [-0.040, 0.000, 0.193]
  Rotation yaw: 90°
```

### Rời dock

```bash
ros2 action send_goal /bot1/undock \
  irobot_create_msgs/action/Undock "{}" \
  --feedback
```

Kết quả:

```text
Result:
    is_docked: false
Goal finished with status: SUCCEEDED
```

### SLAM và lưu map

Chạy trên laptop Dell:

```bash
ros2 launch turtlebot4_navigation slam.launch.py namespace:=bot1
ros2 launch turtlebot4_viz view_navigation.launch.py namespace:=bot1
```

Điều khiển robot đi quét:

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard \
  --ros-args \
  -p stamped:=true \
  -r cmd_vel:=/bot1/cmd_vel
```

Lưu map:

```bash
mkdir -p ~/maps

ros2 run nav2_map_server map_saver_cli \
  -f ~/maps/lab_2026_07_23 \
  --ros-args \
  -p map_subscribe_transient_local:=true \
  -r __ns:=/bot1
```

Các file được tạo trên laptop Dell:

```text
/home/dell/maps/lab_2026_07_23.yaml
/home/dell/maps/lab_2026_07_23.pgm
```

Sau phiên lab, hai file đã được đưa vào repository:

```text
maps/lab_2026_07_23.yaml
maps/lab_2026_07_23.pgm
```

Metadata chính của map:

```text
resolution: 0.050 m/pixel
origin: [-9.128, -4.808, 0]
mode: trinary
```

### Localization bằng AMCL

```bash
ros2 launch turtlebot4_navigation localization.launch.py \
  map:=/home/dell/maps/lab_2026_07_23.yaml \
  namespace:=/bot1
```

Trong RViz đã dùng **2D Pose Estimate** để khai báo vị trí và hướng ban đầu của robot. Sau khi đặt đúng, dữ liệu LiDAR khớp với map và vị trí robot được cập nhật khi robot di chuyển.

Có thể kiểm tra output của AMCL bằng:

```bash
ros2 topic echo --once /bot1/amcl_pose
```

### Navigation bằng Nav2

```bash
ros2 launch turtlebot4_navigation nav2.launch.py namespace:=/bot1
ros2 launch turtlebot4_viz view_navigation.launch.py namespace:=/bot1
```

Kiểm tra action server:

```bash
ros2 action info /bot1/navigate_to_pose
```

Kết quả:

```text
Action servers: 1
    /bot1/bt_navigator
```

Kiểm tra lifecycle ban đầu:

```bash
ros2 lifecycle get /bot1/planner_server
ros2 lifecycle get /bot1/controller_server
ros2 lifecycle get /bot1/bt_navigator
```

Kết quả ban đầu:

```text
planner_server: inactive [2]
controller_server: active [3]
bt_navigator: inactive [2]
```

Reset và khởi động lại navigation stack:

```bash
ros2 service call /bot1/lifecycle_manager_navigation/manage_nodes \
  nav2_msgs/srv/ManageLifecycleNodes \
  "{command: 3}"

ros2 service call /bot1/lifecycle_manager_navigation/manage_nodes \
  nav2_msgs/srv/ManageLifecycleNodes \
  "{command: 0}"
```

Sau khi lifecycle được kích hoạt, robot nhận **Nav2 Goal**, tự tạo đường đi và chạy thành công tới nhiều mục tiêu.

Một goal từng trả về:

```text
status: 6
```

Trạng thái này là `ABORTED`. Các goal khác trong vùng trống chạy thành công, vì vậy lỗi trên được xem là lỗi của một mục tiêu cụ thể, không phải Nav2 ngừng hoạt động hoàn toàn.

## 3. Sự cố và cách xử lý

### LiDAR có publisher nhưng không có dữ liệu

- Sự cố: `/bot1/scan` có publisher nhưng `ros2 topic echo` hết thời gian chờ; LiDAR không quay.
- Cách xử lý: xác nhận `/dev/RPLIDAR -> ttyUSB0`, sau đó gọi `/bot1/start_motor`.
- Trạng thái cuối cùng: LiDAR quay và phát dữ liệu khoảng `7.58 Hz`.

### Nav2 nhận action server nhưng robot không chạy

- Sự cố: `planner_server` và `bt_navigator` ở trạng thái `inactive [2]`.
- Cách xử lý: reset và startup lại các node thông qua `lifecycle_manager_navigation`.
- Trạng thái cuối cùng: Nav2 lập đường và điều khiển robot tới nhiều goal thành công.

### Một goal bị abort

- Sự cố: một goal trả `status: 6`.
- Cách xử lý: chọn lại goal ở vùng trống, tránh costmap sát vật cản.
- Trạng thái cuối cùng: các goal thử sau đó chạy thành công.

### Dock action trên laptop chưa dùng được

- Sự cố: khi gọi action dock trên laptop Dell, CLI báo `The passed action type is invalid`.
- Trạng thái cuối cùng: docking tự động cuối buổi chưa được xác nhận. Cần thử lại từ Raspberry Pi của TurtleBot4 hoặc cài/source đúng interface package trên laptop.
